# 김실장 · 7단계 GPT 상담과 자동 저장

상태: **7단계 완료 · 전체 테스트 206개 통과 · 실제 GPT 상담·자동 저장·재시작 후 유지 검증 완료**.

현재 키는 코디세이에서 제공한 키입니다. OpenAI 공식 서버로 보냈던 요청의 인증 거절은 제공자 설정 불일치였으며, 키가 유효하지 않다는 결론을 내릴 수 없습니다. 2026-10-22 코디세이 전용 서버에서 인증과 제공 모델 목록 조회에 성공했고 `gpt-5-mini`를 확인했습니다.

코디세이 서버는 `response_format`의 JSON 모드·엄격한 JSON Schema 모드를 `unsupported_feature`로 거절했습니다. 기본 Chat Completions 호출을 사용하고 스키마를 프롬프트에 전달한 뒤 Pydantic과 조건 검증을 적용합니다. 고정된 시연 메시지는 실제 GPT 응답으로 표시하지 않습니다.

## 1. 요청이 처리되는 순서

1. Pydantic으로 질문·모드·조건을 검사하고 요청 횟수·동시 요청을 제한합니다.
2. 기존 상담을 읽거나 새 상담 ID를 메모리에 준비합니다. 저장소 읽기 실패·없는 상담·이미 찬 대화는 GPT 호출 전에 중단합니다.
3. `GET /api/data/summary`와 같은 `SummaryService.get()`으로 현재 버전의 요약을 읽습니다. 서버 내부에서 자기 HTTP API를 다시 호출하지 않습니다.
4. 역할 규칙과 요약을 **시스템 프롬프트에 주입**합니다. 현재 조건·질문과 최근 대화를 함께 전달합니다.
5. 선택한 제공자의 GPT 응답을 Pydantic 모델과 사용자 조건으로 검사합니다. 공식 OpenAI는 Responses 구조화 응답을, 코디세이는 기본 Chat Completions와 서버 JSON 검증을 사용합니다.
6. 필요한 경우 잘못된 내용에 대한 수정 요청을 한 번만 합니다. 인증·네트워크·시간 초과·응답 거절은 자동 재시도하지 않습니다.
7. 검증된 계획으로 표시 문장을 만들고 질문·답변·조건·당시 근거를 Firestore에 함께 저장합니다. 저장이 끝난 뒤에만 `200`을 반환합니다.

새 상담은 첫 질문·답변을 포함한 문서를 한 번에 생성합니다. GPT 실패 때문에 빈 상담이 생기지 않습니다. 기존 상담은 읽었던 `revision`과 저장 직전 버전을 비교하며, 동시 변경·삭제가 있으면 덮어쓰지 않습니다. 저장 응답이 불명확할 때에는 목록·상세를 다시 확인한 뒤 재전송합니다. 자동 재전송·중복 제거 키는 이번 버전에 없습니다.

## 2. 김실장에게 전달하는 근거

`app/services/chat_prompt.py`에 역할·한국어 말투·상담 규칙이 있습니다. 상담 종류는 `strategy`, `automation`, `review`입니다.

- 기록은 가상 인물의 시연 데이터입니다. 사용자의 성격·생활·건강이나 업무 효율을 단정하지 않습니다.
- 요약에는 기간·기준일·개수·평균·총 시간·분야·최근 변화·작업 통계·한계를 담습니다. 일별·주별 전체 배열과 원본 메모는 보내지 않습니다.
- 작업 통계와 반복 후보는 각각 총 소요 시간 순 상위 10개를 보내고 제외된 개수를 표시합니다.
- 요약 조회 시점의 `data_revision`과 기간·기준일·개수를 비서 메시지의 `evidence`에 보관합니다. 이후 기록이 바뀌어도 과거 메시지의 근거를 바꾸지 않습니다.
- 모호한 목표·시간·작업 범위는 1~2개 질문으로 확인합니다. 자동화는 설계만 제시하며 효과·절감 시간은 검증 전 가정으로 구분합니다.

‘컨텍스트 주입’은 모델을 재학습시키는 방식이 아닙니다. 요청할 때마다 최신 요약을 함께 읽게 해서 이번 답변의 참고 근거로 쓰는 방식입니다.

## 3. 자연어와 실행 계획 검증

모델은 답변과 함께 `context_update`를 내부 구조로 반환합니다. 각 변경에는 이번 질문의 정확한 인용을 요구합니다. 서버는 인용 존재 여부, 시간 수치·단위, 작업명, 날짜와 선행 관계, 구조화 입력과의 일치를 확인합니다. 확인된 변경만 응답의 `context`와 대화에 저장합니다. 문장의 의미 전체를 수학적으로 보증하는 검증은 아니므로, 화면에서도 반영된 조건을 보여주고 사용자가 수정할 수 있어야 합니다.

이미 확인된 폼·저장 값을 그대로 반복하면 새 변경으로 취급하지 않습니다. 실제로 바뀌는 값에만 새 발언의 근거를 검사합니다. 검증 실패 때는 고정된 오류 분류와 필드명만 기록하고 수정 지시에 활용하며, 키·모델 답변·오류 전문은 로그에 남기지 않습니다. 자동화·조언의 확인 질문은 본문 끝에 함께 표시하고 저장합니다.

가능 시간은 1~1,440분, 작업은 최대 10개입니다. 자연어 마감은 ISO 날짜와 오늘·내일·모레를 확정 대상으로 삼고, 그 외 모호한 날짜는 확인하도록 지시합니다. 구조화 입력에는 유효한 ISO 날짜를 넣습니다. 기존 작업의 중요도·마감·선행 조건을 언급 없이 지우는 변경도 거부합니다.

실행 계획은 다음을 검사합니다.

- 확인된 가능 시간과 같은지.
- 모든 현재 작업을 계획 또는 미루기로 한 번씩 배치했는지.
- 우선순위가 실행 순서대로 1부터 이어지고 선행 작업이 먼저 오는지.
- 양의 정수인 단계 시간과 0 이상인 완충 시간의 합이 가능 시간 이내인지.
- 판단 이유·완료 기준·단계·첫 행동·점검·대안이 있는지.

계획의 표시 문장은 검증한 구조에서 서버가 생성합니다. 모델의 자유 문장에 다른 시간표가 있어도 사용하지 않습니다. 시간과 완료 범위는 추정이며 실제 소요 시간이나 작업 완료를 보증하지 않습니다.

## 4. 환경변수와 호출 제한

키는 백엔드의 비공개 `.env` 또는 배포 환경변수에만 넣습니다. 파일을 명시적으로 읽고 운영체제 값이 우선하며 빈 값도 그대로 우선합니다. 실제 키나 외부 오류 전문은 응답·로그에 포함하지 않습니다.

| 변수 | 기본값·범위 |
| --- | --- |
| `AI_PROVIDER` | `openai` 또는 `codyssey`. 기본 `openai`, 현재 로컬은 `codyssey` |
| `OPENAI_API_KEY` | 선택한 제공자에서 발급한 키. 실제 값은 문서·코드·프론트에 넣지 않음 |
| `OPENAI_MODEL` | 공식 OpenAI 기본 `gpt-6-luna`, 코디세이 기본·현재 `gpt-5-mini` |
| `OPENAI_MAX_OUTPUT_TOKENS` | 코드 기본 `3000`, 현재 로컬·예시 `6000`. 허용 256~6000 |
| `OPENAI_TIMEOUT_SECONDS` | 코드 기본 `40`, 현재 로컬·예시 `60`. 허용 5~60초. SDK의 네트워크 요청 시간 제한 |
| `OPENAI_REASONING_EFFORT` | 공식 OpenAI 기본 `none`, 허용 `none`, `low`, `medium`, `omit`. 코디세이 기본·현재 `omit`이며 기본 호출에서 전송하지 않음 |

설정·클라이언트는 최초 상담 때 읽고 프로세스 안에서 재사용합니다. **제공자·키·모델·제한을 바꾼 뒤 서버를 재시작합니다.** 제공자별 주소는 공식 OpenAI `https://api.openai.com/v1`, 코디세이 `https://copa.codyssey.kr/v1`입니다. 임의 `OPENAI_BASE_URL`로 키를 보내지 않습니다. SDK 자동 재시도는 0회이며 외부 실행 도구는 없습니다.

공식 OpenAI 경로는 `store=False`를 전달합니다. 코디세이는 호환되는 기본 호출만 사용하므로 이 옵션과 추론 강도·응답 형식 옵션을 보내지 않습니다. 제공자 측 보관 정책을 코드 옵션만으로 보장하지 않습니다. 코디세이 경로는 JSON 형태를 프롬프트로 요청하므로 생성 형식 자체가 강제되지는 않으며, 서버 검증을 통과한 응답만 저장·반환합니다.

| 제한 | 현재 기준 |
| --- | --- |
| 질문 | 최대 4,000자 |
| 모델에 보내는 이전 대화 | 최근 최대 12개 메시지·본문 합계 20,000자 |
| 주입 요약 | UTF-8 최대 20,000바이트 |
| 전체 입력 | 메시지·응답 스키마·수정 지시 여유를 합쳐 UTF-8 60,000바이트 이내. 필요 시 오래된 이력부터 제외 |
| 상담 요청 | 클라이언트 주소당 분당 6회·프로세스 전체 분당 10회 |
| 동시 상담 | 프로세스당 최대 2개, 같은 상담은 하나씩 |
| 모델 호출 시도 | 프로세스 전체 최근 24시간 100회. 수정 요청도 포함 |
| 한 상담 요청의 GPT 호출 | 최대 2회: 최초 1회 + 내용 검증 실패 시 수정 1회 |
| 저장 대화 | 전체 이력 최대 100개 메시지·본문 60,000자·문서 500KiB |

입력 한도는 토큰 수를 직접 세는 기능이 아니라 문자열·UTF-8 크기 제한입니다. 출력 토큰 한도에는 모델의 추론 토큰도 포함됩니다. 금액 상한과 동일하지 않으므로 OpenAI 프로젝트의 사용량도 확인합니다.

요청·호출 횟수 카운터는 메모리에 있어 재시작하면 초기화되고 여러 서버 프로세스 사이에 공유되지 않습니다. 이번 로컬·단일 프로세스 시연의 제어입니다. 프록시가 전달한 임의 `X-Forwarded-For` 헤더는 코드에서 직접 신뢰하지 않습니다. 배포 시 실제 프록시 설정과 식별 기준도 점검합니다.

## 5. Swagger에서 상담하기

서버를 시작하고 [Swagger](http://127.0.0.1:8000/docs)의 **김실장 상담 → POST /api/chat**을 펼칩니다.

```json
{
  "message": "지원서 작성과 포트폴리오 수정 중 무엇부터 어떻게 할까요?",
  "mode": "strategy",
  "context": {
    "goal": "지원서 초안 완성",
    "available_minutes": 120,
    "tasks": [
      {"id": "t1", "title": "지원서 작성", "due_date": "2026-10-22", "importance": "high", "depends_on": []},
      {"id": "t2", "title": "포트폴리오 수정", "due_date": "2026-10-25", "importance": "medium", "depends_on": []}
    ],
    "constraints": "이번 범위는 제출이 아닌 초안 작성"
  }
}
```

성공하면 `conversation_id`, 저장된 비서 `message`, 최신 `context`를 받습니다. [API 계약](API_CONTRACT.md)의 응답 규칙을 따릅니다. 반환된 ID를 사용해 `GET /api/conversations/{id}`로 전체 메시지를 읽습니다.

추가 질문 예시입니다. 자연어에서 확인된 60분을 조건에 반영합니다.

```json
{
  "conversation_id": "성공 응답에서 받은 ID",
  "message": "이번에 쓸 수 있는 시간이 60분으로 줄었어요. 지원서 초안에 집중해서 다시 계획해 주세요."
}
```

이 예시 ID는 실제 값으로 교체해야 합니다. 대화 불러오기 자체는 GPT를 호출하지 않습니다. 위 요청 예시는 테스트용 시나리오이며 실제 성공 답변의 증거가 아닙니다.

## 6. 오류와 검증 결과

`503`은 키 누락·인증 거절·저장소/요약 사용 불가, `429`는 로컬 횟수·OpenAI 요청/결제 한도, `502`는 외부 API 오류·응답 거절·수정 후에도 잘못된 계획, `504`는 GPT 시간 초과입니다. 키 오류를 안내 문장이나 정상 상담으로 저장하지 않습니다.

오프라인 테스트는 실제 HTTP 라우터·Firestore 어댑터 로직과 OpenAI SDK의 모의 HTTP 전송을 검사합니다. 시스템 프롬프트 주입, 최신 요약·대화 맥락, 시간/ID/선행 관계 검증, 자연어 조건 반영, 수정 횟수, 오류 비노출, 자동 저장의 원자성·충돌·한도와 호출 제한을 확인합니다. 이 테스트는 외부 클라우드 성공의 대체 증거가 아닙니다.

2026-10-22 코디세이 제공 `gpt-5-mini`로 다음 다섯 시나리오의 `200` 응답과 Firestore 저장을 확인했습니다.

| 실제 요청 | 확인한 결과 |
| --- | --- |
| 120분 동안 지원서·포트폴리오 작업 | 작업 110분 + 완충 10분. 우선순위·완료 기준·단계·첫 행동·점검·대안 포함 |
| 같은 대화에서 가능 시간을 60분으로 변경 | 지원서 55분 + 완충 5분. 포트폴리오는 미루고 기존 목표·마감 유지 |
| 제안서 반복 업무 자동화 설계 | 제안서 20건·1372분, 자료 취합 40건·1367분을 근거로 자동화/사람 확인·작은 검증·도구 후보·확인 질문 제시. 효과는 미검증 가정으로 구분 |
| 가상 기록 회고 | 150건·6524분·평균 43.49분·최근 변화 -5.75%를 설명하고 관측·해석·한계를 구분 |
