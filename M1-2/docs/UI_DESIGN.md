# 김실장 웹 화면의 설계 기준

2026-10-27, 사용자가 선택한 **“차분하고 세련된 — 정돈된 화면과 감각적인 색 포인트”**를 반영했습니다. 구체적인 색상과 서체는 구현자가 정했으며, 상세 제품 요구와 API 동작은 [PRODUCT_SPEC.md](PRODUCT_SPEC.md)를 유지합니다.

## 방향과 근거

- 사용 장면: 사용자가 필요할 때 여는 개인 업무 상담 도구. 모드: Operate.
- 스타일: design-taste-frontend의 Framed sheet, seed `2102444201`. 기존 화면을 refine/colorize했습니다. 이전의 Achromatic ledger(seed `621370104`)는 8단계 첫 구현 기록입니다.
- 얼굴: 은은한 푸른 회색 `#edf3f8` 틀과 흰 작업 면, 잉크 블루 `#234e70` 주요 버튼. 본문은 `#233b50`, 보조 글자는 `#5b7082`입니다. 별도 그림자 없이 면과 간격으로 계층을 만듭니다.
- 서체: IBM Plex Sans와 한국어 IBM Plex Sans KR을 실제 로드합니다. 네트워크가 없으면 브라우저의 sans-serif로 읽을 수 있습니다.
- 표식: 문서 모서리와 체크를 결합한 기존 SVG를 잉크 블루로 정제했습니다. 장식 그림 대신 ‘다음 행동을 정한다’는 목적을 유지합니다.
- 고유 요소: 실행 계획의 ‘작업 시간 + 여유 시간 / 가능 시간’, 이번에 할 일과 다음으로 미룰 일. 당시 메시지의 상담 조건을 사용합니다.
- 색은 주요 버튼·선택된 메뉴·데이터·포커스에 같은 의미로 씁니다. 시간 증감은 좋고 나쁨으로 색칠하지 않습니다.
- 카드에는 그림자를 넣지 않고, 일시적인 알림에만 그림자를 둡니다. 빠진 측정값은 `—`이며 날짜 구간의 기호와 구분합니다.
- 화면이 좁으면 네 메뉴를 한 줄로 보여줍니다. 시작 질문은 짧은 버튼으로 묶고, 작업 메모는 네이티브 펼치기로 읽도록 정리했습니다.

| 화면 | 가장 먼저 답할 질문 | 주요 행동 |

| 상담 | 지금 무엇부터 어떻게 시작할까? | 질문 전송, 선택 상황 입력 |
| 작업 기록 | 어떤 일을 얼마나 했고 기록을 어떻게 고칠까? | 추가·수정·대상 확인 후 삭제 |

| 이전 상담 | 어떤 대화부터 이어갈까? | 메시지·당시 조건 불러오기 |

## 데이터와 상태

기록·요약·대화는 API 응답에서 렌더링합니다. 수치를 장식 목적으로 만들지 않습니다. 사용 데이터는 `data/work_records.json`에서 시작한 가상 기록 150건이며 실제 개인 생활을 추론하지 않습니다. 요약의 기준일은 현재 날짜와 분리합니다.

기록이 없는 날짜는 휴식·0분으로 해석하지 않습니다. 주별 자료는 첫 기록일부터 7일씩 묶은 서버 결과를 그대로 보여줍니다. 자동화 후보 선택은 질문 초안만 채우며 유료 요청을 보내지 않습니다. 입력·AI 출력·메모는 텍스트로 표시합니다.

로딩·빈 상태·실패·재시도·저장 완료를 구분합니다. 실패한 질문과 조건을 보존하고 요청을 자동 재전송하지 않습니다. 삭제 확인은 기록 한 건과 상담 전체를 구분합니다. 새 상담·다른 상담 불러오기는 전송 중 차단합니다.

## 검증 방식

브라우저 제어는 이 환경이 제공하는 CUA만 사용했습니다. 별도 브라우저를 띄우는 디자인 검사기 대신 CUA에서 DOM 너비·제목·포커스를 측정하고 캡처를 직접 확인했습니다. 390×844, 768×1024, 1440×900에서 네 화면 모두 가로 넘침이 없었습니다. 현재 사용자 창 크기 545×704도 확인했습니다.

정적 스타일 검사: 오류 0건. 알림 그림자는 실제로 떠 있는 요소라 허용했고, `—`는 날짜 범위·측정값 부재를 나타내는 표기입니다. Impeccable 검사에서 발견한 메뉴 호버 대비는 더 짙은 잉크로 수정했습니다. 이전 DESIGN.md와 다른 서체·색상·크기 경고는 사용자가 요청한 개선에 따른 변경이므로 현재 구현 문서에 반영합니다. 본문 11.58:1, 보조 글자 5.14:1(흰 면), 주요 버튼 8.77:1, 입력 경계 3.40:1로 확인했습니다.

이번에는 HTML/CSS/JavaScript를 직접 구현했습니다. 승인된 이미지 시안이나 브랜드 자료는 없습니다. 구현 범위와 실제 기능 검증은 [FRONTEND.md](FRONTEND.md)에 정리합니다.

화면 개선에서는 GPT 호출이나 데이터 변경을 하지 않았습니다. 기존 150건·6,524분, 이전 상담은 읽기만 하며 확인했습니다.

## 2026-10-28 상담 이어쓰기 개선

첫 질문의 안내 화면은 유지하고, 전송 이후에는 참고 열을 기본 접은 넓은 채팅 화면으로 전환합니다. 대화 본문은 16px, 줄 간격 1.9이며 사용자 메시지는 오른쪽의 옅은 면, 답변은 읽기 면으로 구분합니다. 기존 서체·색·평평한 작업 면을 유지합니다. 조건은 입력칸 위에서 펼치며 새 답변은 시작 부분부터 읽습니다. 새 상담은 안내 화면으로 돌아갑니다.

‘자동 저장’의 목적지는 ‘이전 상담’으로 표시합니다. 완료한 일은 별도로 ‘작업 기록’에 등록한다는 안내를 대화 목록에 둡니다. 브라우저 초안과 서버의 저장 상담은 목록에서 구분합니다. 복원·불확실한 전송·조회 실패의 동작은 [FRONTEND.md](FRONTEND.md)를 따릅니다. 실제 검증 범위와 한계는 [상담 복원 검증](CHAT_RECOVERY_QA.md)에 기록합니다.
