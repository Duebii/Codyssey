# 김실장 · 1단계 화면 및 상담 설계

상태: **1단계 설계 기준 확정 · 8단계 웹 화면 구현 완료**

이 문서는 현재 대화에서 정한 목적과 사용 방식을 첫 버전의 구현 기준으로 구체화합니다. 사용성 검증과 시각 디자인은 이후 화면 구현 단계에서 진행합니다.

## 1. 목적과 범위

김실장은 사용자가 질문할 때 다음을 함께 정하는 AI 업무 전략 비서입니다.

1. 지금 무엇부터 해야 하는가: 우선순위와 판단 근거.
2. 어떻게 끝낼 것인가: 완료 기준, 단계, 시간 배분, 첫 행동과 대안.
3. 반복되는 일을 어떻게 개선할 것인가: 개선·자동화 후보와 실행 방법.

첫 버전은 더미 작업 기록 150건을 사용합니다. 시연 중 입력한 새 작업 기록도 가상 데이터로 취급합니다. 사용자의 실제 생활이나 업무 이력으로 간주하지 않습니다.

사용자에게 먼저 연락하거나 알림을 보내지 않습니다. 외부 도구 실행·메시지 발송·파일 수정·자동화 배포는 수행하지 않습니다. 실제 자동화 실행과 미완료 작업의 지속 추적은 후속 범위입니다.

## 2. 화면 구성과 이동

기본 화면은 **김실장 상담**입니다. 네 화면으로 이동하는 메뉴를 항상 제공합니다. 데스크톱은 왼쪽 메뉴, 좁은 화면은 상단의 줄바꿈 가능한 메뉴를 사용합니다. 8단계의 색·서체·간격은 [디자인 기준](UI_DESIGN.md), 사용법은 [웹 화면 안내](FRONTEND.md)에 정리했습니다.

| 화면 | 주요 내용 | 사용자의 행동 | 확인할 결과 |
| --- | --- | --- | --- |
| 김실장 상담 | 대화, 상담 종류, 상황 입력, 참고 기록 요약 | 질문·추가 정보 입력, 전송, 새 상담 | 확인 질문 또는 우선순위·실행 전략·자동화 설계 |
| 작업 기록 | 기록 목록, 추가·수정 폼, 삭제 확인 | 날짜·작업명·분야·시간·메모 입력 | 저장 결과, 갱신된 목록과 요약 |
| 기록 요약 | 데이터 기간·개수·통계·변화·반복 작업 | 분석 내용을 확인하고 상담으로 이동 | 어떤 데이터를 근거로 상담하는지 파악 |
| 이전 상담 | 대화 제목·마지막 갱신 시각·미리보기 | 선택, 이어서 상담, 삭제 | 선택한 대화의 메시지와 상담 조건 복원 |

모든 화면에 **시연용 가상 데이터** 표시를 둡니다. 요약을 보여줄 때 분석 기준일과 기록 개수를 함께 표시합니다. 현재 시각과 과거 데이터의 기준일을 구분합니다.

### 상담 화면 배치

- 상단: 김실장 이름, 현재 상담 종류, 새 상담 버튼.
- 본문: 사용자·비서 메시지, 답변 근거와 구조화된 실행 계획.
- 참고 영역: 기록 기간·개수·최근 변화, 기록 요약 화면으로 가는 링크.
- 입력 영역: 질문, 접을 수 있는 상황 입력, 전송 버튼.

상황 입력은 선택 사항입니다. 첫 방문에 긴 설문을 요구하지 않습니다. 상황 입력을 접어도 작성한 내용은 유지됩니다.

### 주요 이동 흐름

- 처음 사용: 상담 → 참고 요약 확인 → 질문 → 필요한 정보 확인 → 전략 제안.
- 기록 관리: 작업 기록 → 추가·수정·삭제 → 최신 목록·요약 확인 → 상담.
- 자동화 탐색: 기록 요약의 반복 작업 → 자동화 상담으로 이동 → 작업 과정을 확인 → 설계 제안.
- 이어서 사용: 이전 상담 → 대화 선택 → 메시지·조건 복원 → 추가 질문.

작업을 선택해 자동화 상담으로 이동하면 작업명을 질문 초안에 채웁니다. 사용자 확인 없이 질문을 자동 전송하지 않습니다.

## 3. 입력과 상태 처리

### 상담 입력

| 항목 | 필수 여부 | 화면에서의 의미 |
| --- | --- | --- |
| 질문 | 필수 | 질문 한 줄로 시작 가능 |
| 상담 종류 | 기본값 제공 | 우선순위·실행 전략 / 자동화 설계 / 기록 돌아보기 |
| 현재 목표 | 선택 | 오늘의 목표 또는 현재 집중할 방향 |
| 오늘 할 일 | 선택 | 작업명, 마감일, 중요도, 선행 작업 |
| 가능 시간 | 선택 | 이번에 쓸 수 있는 총 시간, 분 |
| 제약·참고 사항 | 선택 | 사용 도구, 고정 일정, 필요한 자료 등 |

자연어로 전달한 정보도 상담에 활용합니다. 마감·시간·범위에 중요한 모호함이 있으면 짧게 확인합니다. 명시하지 않은 값을 확정된 조건으로 저장하지 않습니다.

사용자가 명시한 변경은 기존 조건보다 우선합니다. 앞선 조건과 충돌하고 어느 것이 최신인지 불분명하면 확인합니다. 할 일의 선행 관계가 자기 자신을 가리키거나 순환하면 조건을 수정하도록 안내합니다.

### 공통 상태

- 전송 중: 전송·상담 전환·대화 불러오기 버튼을 잠시 막아 응답이 다른 대화에 붙지 않게 하고, 진 행 상태를 표시합니다.
- 저장·수정 중: 해당 폼의 중복 제출을 막습니다.
- 실패: 작성 중인 내용을 보존하고 재시도 방법을 보여줍니다. 저장 완료 표시를 먼저 띄우지 않습니다.
- 삭제: 대상 이름과 삭제 범위를 확인한 뒤 실행합니다. 원본 작업 삭제와 대화 삭제를 구분합니다.
- 빈 기록: 0건임을 표시하고 첫 기록 입력을 안내합니다. 통계를 0분으로 꾸며 표시하지 않습니다.
- 빈 대화: 첫 상담 시작 버튼을 제공합니다.
- 오래 걸리는 첫 접속: 서버 준비 중일 수 있음을 안내하고 재시도를 제공합니다.
- 응답 후 화면은 사용자의 스크롤 위치를 존중하고, 새 메시지로 이동할 수 있게 합니다.

비서의 출력과 메모는 안전한 텍스트로 렌더링합니다. 사용자 입력이나 AI 출력의 HTML을 그대로 실행하지 않습니다. 키보드로 입력·이동·전송할 수 있어야 하며, 로딩·오류 상태를 텍스트로도 전달합니다.

## 4. 상담 규칙

### 기본 태도

- 한국어 존댓말을 기본으로, 명료하고 부담 없는 말투를 사용합니다.
- 결정의 이유를 먼저 설명하고 사용자가 선택·수정할 수 있게 제안합니다.
- 관심사 수나 시간 기록으로 성격·건강 상태·의지·능력을 판단하지 않습니다.
- 없는 기록·마감·성과·도구 기능을 만들어내지 않습니다.
- 현재 시연 데이터는 항상 가상 사용자의 기록으로 설명합니다. 실제 사용자에게 적용할 때는 가정임을 밝힙니다.

### 우선순위 결정

다음 요소를 함께 고려하고 사용한 근거를 답변에 표시합니다.

| 요소 | 판단 방식 |
| --- | --- |
| 선행 관계 | 해당 작업을 시작하려면 먼저 끝내야 하는 작업 확인 |
| 마감과 미이행 영향 | 가까운 마감과 놓쳤을 때의 영향을 확인 |
| 사용자 목표와 중요도 | 사용자가 현재 중요하게 여기는 목표 반영 |
| 가능 시간과 제약 | 지금 완료하거나 의미 있게 진행할 수 있는 분량인지 확인 |
| 과거 소요 시간 | 같은 작업의 기록을 참고하되, 현재 범위와 같은지 확인 |

단순한 시간 사용량을 중요도 점수로 바꾸지 않습니다. 정보가 비슷하면 동순위나 선택지를 제시할 수 있습니다. 사용자가 이유를 들어 순서를 바꾸면 그 선택을 반영해 전략을 조정합니다.

### 실행 전략 답변

순서는 **우선순위와 이유 → 완료 기준 → 단계·시간 배분 → 첫 행동 → 점검·대안**입니다.

실행 계획에는 다음을 포함합니다.

- 이번에 할 작업과 다음으로 미룰 작업.
- 이번 작업의 구체적인 완료 기준.
- 실행 단계와 단계별 예상 분, 휴식·완충 시간.
- 지금 시작할 수 있는 첫 행동.
- 중간 점검 시점과 확인할 결과물.
- 시간이 부족하거나 선행 조건이 충족되지 않을 때의 대안.
- 기록 근거와 현재 상담에서 세운 가정.

**각 단계의 시간 합계 + 휴식·완충 시간은 사용자가 확인한 가능 시간을 넘지 않아야 합니다.** 맞추기 어려우면 범위를 줄이거나 다른 작업을 미루는 선택을 설명합니다. 마감까지 불가능한 분량을 완료할 수 있다고 약속하지 않습니다.

가능 시간이 없으면 일정표를 확정하지 않고 먼저 확인합니다. 우선순위나 첫 행동만 요청한 경우에는 필요한 정보 안에서 먼저 답할 수 있습니다. 확인 질문은 한 번에 핵심 1~2개로 제한하며, 가정에 기반한 초안은 확정안과 구분합니다.

### 자동화 설계 답변

반복 횟수와 누적 시간은 후보를 찾는 근거입니다. 작업 과정을 모르면 아래 중 부족한 내용을 먼저 확인합니다.

- 어떤 자료를 입력받는가.
- 어디에서 어떤 도구로 처리하는가.
- 어떤 결과물이 필요한가.
- 반복 주기와 예외, 사람의 판단·검토 단계는 무엇인가.

설계 답변은 **후보와 기록 근거 → 현재 과정 → 자동화할 단계 → 사람이 확인할 단계 → 필요한 방법·도구 → 작은 검증 순서 → 구축 노력과 예상 효과 → 확인할 조건** 순서입니다.

외부 도구의 지원 기능·권한·최신 가격을 확인하지 않았다면 확인이 필요하다고 표시합니다. 절감 시간은 실제 측정 결과와 추정치를 구분합니다. 예상 효과를 말할 때는 수행 횟수와 가정한 절감 분을 함께 밝히고 구축·유지 비용도 고려합니다.

### 기록 돌아보기 답변

기간·개수·수치와 변화의 기준을 먼저 설명합니다. 그다음 기록에서 보이는 패턴과 확인이 필요한 해석을 구분합니다. 기록된 시간이 줄었다는 이유만으로 효율이 좋아졌다거나 의욕이 떨어졌다고 판단하지 않습니다.

## 5. 기록·계획·대화의 구분

| 정보 | 저장·사용 방식 |
| --- | --- |
| 완료한 작업의 수행 기록 | `data`에 저장. 통계와 시간 추정의 근거 |
| 앞으로 할 일과 마감 | 해당 상담의 조건으로 `conversations`에 보관 |
| 제안한 실행 계획·자동화 설계 | 비서 메시지에 보관. 실제 수행 결과로 집계하지 않음 |
| 사용자가 말한 실행 결과 | 대화에 보관. 기록 추가 화면에서 명시적으로 저장한 뒤에만 분석 데이터가 됨 |
| 분석 요약 | `summaries`에 보관. 현재 분석 대상 기록으로부터 계산 |

김실장의 제안이 실제로 실행됐다고 간주하지 않습니다. 전략이 자동으로 학습되거나 실제 도구가 실행됐다고 표현하지 않습니다.

이전 상담을 불러오면 과거 답변은 당시의 근거와 함께 보존합니다. 새 질문에는 최신 요약을 사용하고, 기준일·기록 수가 달라졌으면 새 근거를 표시합니다. 상담의 할 일이 아직 미완료인지 알 수 없으면 확인합니다.

## 6. 구현 기준 연결

- 기록 필드·검증 규칙·API 요청과 응답·분석 계산은 [API 및 데이터 계약](API_CONTRACT.md)을 따릅니다.
- 현재 더미데이터의 특성과 검증은 [데이터 설명](DATASET.md)을 따릅니다.
- 실제 개발 순서는 [워크리스트](../WORKLIST.md)를 따릅니다.

첫 버전의 서버는 원본 기록에서 계산한 수치를 제공하고, AI는 그 수치를 근거로 해석과 전략을 제안합니다. UI가 보여주는 실행 계획과 대화 본문은 같은 구조화된 계획을 사용합니다.

## 7. 구현 후 확인할 대표 시나리오

아래는 후속 단계에서 검증할 기준이며 현재 동작 확인 결과가 아닙니다.

| 상황 | 기대 동작 |
| --- | --- |
| “뭐부터 할까요?”만 입력 | 할 일·목표 등 판단에 필요한 정보 1~2개 질문 |
| 마감이 다른 할 일과 120분을 입력 | 근거 있는 순서와 총 120분 이내의 실행 계획 제안 |
| “이제 30분밖에 없어요”로 변경 | 앞선 계획을 조정하고 완료 범위·미룰 일을 설명 |
| 작업 단계 합계가 시간 한도를 초과 | 서버에서 정상 계획으로 통과시키지 않음 |
| 자료 취합을 자동화해 달라고 요청 | 기록 근거 제시 후 입력·출력·사용 도구·검토 단계 확인 |
| 더미 기록을 보고 “내가 취업에 집중하네?”라고 질문 | 가상 사용자 기록임을 설명하고 실제 우선순위로 단정하지 않음 |
| 실제 기록이 없거나 요약 조회가 실패 | 근거 부족 또는 조회 실패를 알리고 수치를 만들지 않음 |
| 기록을 수정한 뒤 이전 상담에서 새 질문 | 과거 메시지는 보존하고 새 답변은 최신 요약 참고 |
| 실행 전략을 제안받기만 함 | 원본 작업 기록 수와 통계는 변하지 않음 |
| 대화를 불러온 뒤 목표를 변경 | 이전 조건을 복원하고 명시한 새 목표를 반영 |

## 8. 1단계 결정 사항

기본 화면·메뉴·상담 종류, 입력 항목, 답변 형식, 자동화 설계 범위, 계획과 기록의 구분을 위 내용으로 정합니다. 필드와 통계의 상세 기준은 연결된 API 계약으로 고정합니다. 구현 중 범위를 바꾸려면 해당 문서와 워크리스트에 함께 반영합니다.
