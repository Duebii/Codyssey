# 상담 복원과 대화 화면 검증 · 2026-10-28

질문 작성 → 브라우저 임시 보관 → 성공한 상담은 기존 API로 Firestore에 저장 → GET으로 대화 복원 → 후속 질문을 이어 쓰는 흐름을 점검했습니다. 상담이 완료한 작업 기록으로 자동 변환되지는 않습니다.

## 확인한 문제와 변경

- 기존 화면은 대화와 초안을 메모리에만 보유해 페이지가 다시 만들어지면 빈 첫 화면을 표시했습니다. 브라우저 탭을 단순 전환한 것만으로 페이지가 재생성됐는지는 직접 재현하지 못했습니다. 페이지 재로드·새 탭 복원으로 동일한 손실 경로를 확인하고 보완했습니다.
- 사용자가 보고한 당일 상담은 서버 목록에서 질문·답변 총 4개가 저장된 것을 확인했습니다. 대화 내용은 공개 문서나 캡처에 옮기지 않았습니다.
- 저장 목적지를 ‘이전 상담’으로 명확히 표시합니다. 마지막 상담 ID는 브라우저에 보관하고 메시지는 GET으로 불러옵니다.
- 미전송 질문·원래 조건·변경 조건·종류·읽던 위치를 탭에 보관하고 브라우저에 백업합니다. 다른 상담·새 상담을 열어도 초안은 임시 목록에서 다시 엽니다.
- 응답 대기 중 다시 접속해도 GPT 요청을 자동 재전송하지 않습니다. 이미 저장된 후속 질문을 확인하면 임시 전송 표시를 정리합니다. 조회 실패 시 초안을 보존하고 기존 상담을 복구하기 전 전송을 차단합니다.
- 첫 질문 전 안내 화면, 질문 이후 넓은 채팅 화면으로 나눕니다. 긴 답변은 시작부터 읽고 참고 열은 필요할 때 펼칩니다.

## 검증

외부 키·Firestore·GPT를 사용하지 않는 분리된 HTTP 시험 서버와 CUA 브라우저로 확인했습니다. 고정 응답에는 시험용임을 표시했습니다.

| 흐름 | 결과 |
| --- | --- |
| 질문·목표·가능 시간·할 일 입력 → 메뉴 이동 → 새로고침 | 원문·조건 복원 |
| 첫 전송 성공 → 채팅 화면 → 후속 초안 작성 → 새로고침 | 서버 메시지와 후속 초안 함께 복원 |
| 새 상담 → 이전 상담 목록 → 해당 초안 열기 | 각 상담의 초안 유지 |
| 새 탭 열기 → 백업 복원 → 서로 다른 질문 작성 | 새 탭 복원, 기존 탭 원문 유지 |
| 연결 끊김 → 새로고침 | 질문 유지, 저장 확인 안내, 자동 재전송 없음 |
| 응답 대기 중 새로고침 → 서버 저장 뒤 다시 불러오기 | 완료된 메시지 4개 복원, 이미 저장된 질문의 미전송 표시 정리 |
| 기존 상담 GET 실패 → 재시도 | 질문 유지, 복원 전 전송 차단, 성공 뒤 이어쓰기 |
| 참고 기록 펼치기·닫기 | 대화 화면에서 접근 가능 |

자동 검증: Node 20개(기존 14개 + 복원·저장소 장애·탭 분리 등 6개), Python 프론트 빌드 11개 통과. 기존 백엔드 기능의 이전 전체 시험 결과는 README의 날짜별 기록을 따릅니다. 이번 변경에서 유료 GPT를 추가 호출하거나 기존 작업·상담을 수정하지 않았습니다.

브라우저 데이터 삭제·다른 브라우저·다른 웹 주소 사이의 미전송 초안 이동은 지원하지 않습니다. 서버에 저장한 상담은 별도로 불러올 수 있습니다. 여러 탭의 초안을 실시간으로 합치지는 않으며 새 탭의 시작점은 마지막 브라우저 백업입니다. 실제 기기에서 메모리 부족으로 탭이 폐기되는 상황, 모바일 가상 키보드, 물리 터치·스크린 리더는 직접 시험하지 않았습니다.
