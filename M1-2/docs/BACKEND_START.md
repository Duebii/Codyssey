# 김실장 · 3단계 로컬 서버 실행 안내

상태: **서버 기반·실제 기록 CRUD·시계열 요약·6단계 대화 저장 검증 완료**. 더미 기록 150건·최신 요약·시연용 대화를 저장했습니다. 상세 결과는 [Firestore 안내](FIRESTORE.md), [요약 안내](SUMMARY.md), [대화 기록 안내](CONVERSATIONS.md)를 참고합니다.

Firebase 프로젝트나 OpenAI API 키가 없어도 이 단계는 실행할 수 있습니다. 서버 시작 시 공개 로컬 설정만 검증하고, 외부 SDK 초기화·인증·네트워크 호출을 하지 않습니다.

## 1. 실행과 접속

`M1-2` 폴더에서 실행합니다. 2단계 가상환경과 패키지가 준비돼 있어야 합니다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

- Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- 서버 상태: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)
- API 정의: [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json)

서버를 실행한 터미널에서 `Ctrl+C`로 종료합니다. 개발 중 자동 재시작이 필요 없으면 `--reload`를 빼고 실행할 수 있습니다. Windows 샌드박스에서는 비동기 서버와 테스트의 로컬 소켓 사용 권한이 필요할 수 있습니다. 이번 실제 서버·API 테스트도 해당 권한을 허용해 확인했습니다.

서버 상태 응답은 다음과 같습니다.

```json
{
  "status": "ok",
  "service": "김실장",
  "stage": 7,
  "storage": "not_checked",
  "ai": "not_checked"
}
```

`status: ok`는 서버 실행 상태입니다. 이 요청은 외부 저장소나 GPT를 탐색하지 않으므로 `storage`와 `ai`는 `not_checked`입니다. 각 실제 요청으로 연결 결과를 확인해야 합니다.

## 2. 현재 사용할 수 있는 기능

| 기능 | 현재 결과 |
| --- | --- |
| 서버 상태 조회 | `200`, 실행 상태·연결 전 상태 표시 |
| Swagger·OpenAPI | `200`, 경로·요청 모델·오류 형태 확인 |
| 잘못된 작업·질문·상담 조건 입력 | `422`, 문제가 있는 입력 항목 안내 |
| 없는 주소 요청 | `404`, 공통 오류 형식 |
| 지원하지 않는 요청 방식 | `405`, 공통 오류 형식 |
| 허용한 로컬 출처의 요청 | CORS 응답 헤더 제공 |
| 기록 CRUD에 유효한 요청 | 인증 정보가 없으면 `503`. 실제 연결 후에는 생성 `201`·조회/수정 `200`·삭제 `204` |
| 대화 API에 유효한 요청 | 생성 `201`, 목록·전체 불러오기 `200`, 삭제 `204`. 설정이 없으면 `503` |
| 요약 요청 | `200`, 버전 확인 후 최신 분석·요약. 설정·재계산 실패는 `503` |
| 상담 요청 | 검증·GPT 생성·저장까지 성공하면 `200`. 코디세이 제공 키로 실제 확인. 설정이 없으면 `503` |

기록 CRUD·요약·대화 저장은 실제 Firestore 어댑터로 연결했고 Swagger에 성공 응답과 오류를 함께 정의했습니다. GPT 상담·구조화 계획 검증·자동 저장도 구현했으며 [상담 안내](CHAT.md)에 호출 제한과 실제 검증 결과를 정리했습니다. 성공 응답 기준은 [API 계약](API_CONTRACT.md)을 따릅니다.

운영 코드에서 JSON·메모리 저장으로 자동 대체하지 않습니다. 기록 150건·요약·고정된 시연용 메시지를 보존하며, 2026-10-22 코디세이 제공 키로 실제 GPT 상담 4개·메시지 10개의 저장과 재시작 후 유지를 확인했습니다.

## 3. Swagger에서 직접 확인하기

1. `/docs`를 엽니다.
2. **GET /api/health**를 펼치고 `Try it out` → `Execute`를 눌러 `200` 응답을 확인합니다.
3. **POST /api/data**를 펼치고 아래 예시를 입력합니다.

```json
{
  "date": "2026-10-20",
  "value": -10,
  "memo": "시연용",
  "task_name": "자료 취합",
  "category": "프리랜서",
  "estimated_minutes": 30
}
```

4. `Execute`를 누르면 `422`와 `fields: ["value"]`를 확인할 수 있습니다.
5. `value`를 `40`으로 바꾸면 입력 검증을 통과합니다. 현재처럼 Firebase 인증을 설정한 환경에서는 `201`로 실제 저장하고 요약도 갱신합니다. 인증이 없으면 `503`입니다. 성공 시 `warning`이 있는지도 확인합니다.
6. **POST /api/chat**에서도 질문 없이 보내거나 가능 시간에 문자열·음수를 넣으면 입력 검증 오류를 확인할 수 있습니다.
7. **GET /api/data/summary**를 실행하면 기록 수·평균·추세와 원본 버전·요약 생성 시각을 확인할 수 있습니다.

## 4. 파일을 나눈 기준

```text
M1-2/
  main.py                   서버 실행 진입점
  app/
    main.py                 앱 구성과 CORS 연결
    core/                   시작 설정과 공통 오류 처리
    routers/                HTTP 주소·요청 방식과 서비스 연결
    schemas/                Pydantic 요청·응답 모델
    services/               기록 처리·시계열 계산·요약 최신성·서버 상태
    repositories/           Firestore 원본·요약·버전의 저장 계약과 트랜잭션
  tests/
    test_api.py             실제 HTTP 요청으로 뼈대 검증
    test_environment.py     2단계 환경 설정 점검
    test_records.py         실제 저장소 어댑터의 CRUD를 오프라인 검증
    test_summaries.py       시계열 계산·요약 갱신·충돌·실패 검증
```

라우터는 요청을 받고 서비스로 연결합니다. 스키마는 서비스 호출 전에 입력을 검사합니다. 서비스는 HTTP 주소나 인증 JSON을 직접 처리하지 않습니다. 저장소는 저장 방식에 대한 책임을 맡으며 실제 Firestore 어댑터는 4단계에서 추가했습니다.

`ManagerService`는 기록 처리를 `RecordService`, 요약을 `SummaryService`, 대화를 `ConversationService`, GPT 상담을 `ChatService`로 위임합니다. 계산은 DB에 의존하지 않는 `analysis.py`가 담당합니다. 실제 앱은 같은 지연 Firebase 클라이언트를 공유하고, 테스트는 기록·대화 저장소와 AI 어댑터를 각각 주입할 수 있습니다. OpenAI SDK도 최초 상담 요청에서 초기화합니다.

## 5. 요청 검증과 오류 처리

- 날짜는 유효한 `YYYY-MM-DD` 형식이어야 하고, 완료 작업의 날짜는 한국 기준 오늘 이후일 수 없습니다.
- 소요·예상 시간과 가능 시간은 1~1,440 사이 정수입니다. 문자열 숫자·소수·불리언을 시간으로 바꾸지 않습니다.
- 필수 항목·문자열 길이·분야·상담 종류를 검사하고, 요청에 없는 규칙의 필드는 거부합니다.
- 같은 상담 안의 작업 ID 중복, 없는 선행 작업, 자기 참조·순환을 거부합니다.
- `context`에서 생략한 값과 명시적인 `null`·빈 작업 배열을 구분하고, 메시지 저장 시 기존 조건과 병합합니다. 과거 메시지의 조건은 보존합니다.
- 하루 여러 작업의 합계 제한은 4단계에서 Firestore 트랜잭션 안에 구현했습니다. 한 건의 형식 검증은 저장소 호출 전에 수행합니다.
- 오류는 `{ "error": { "code": ..., "message": ..., "fields": [...] } }` 형태로 통일합니다. 입력값·원본 예외·인증 정보를 그대로 응답에 넣지 않습니다.
- 예상하지 못한 오류에도 안전한 `500` 응답을 제공하고, 로그에는 원본 오류 문자열 대신 오류 종류만 남깁니다.

기록 저장소에서 실제로 해당 출처의 ID가 없으면 `404`입니다. 미연결 상태에서는 존재 여부를 추측하지 않고 `503`을 반환합니다. 실제 클라우드에서 CRUD와 없는 기록의 `404`, 한도 초과·잘못된 페이지의 `422`를 확인했습니다. 인증·RPC 장애에 대한 안전한 예외 처리는 오프라인 테스트 범위입니다.

## 6. 시작 설정과 CORS

- 프로젝트 루트 `.env`와 운영체제 환경변수를 읽고, 운영체제 값이 우선합니다.
- `APP_ENV`, `ALLOWED_ORIGINS`, `API_BASE_URL`의 형식이 잘못되면 값 자체를 노출하지 않는 시작 오류를 냅니다.
- 공개 설정이 생략된 개발 환경에서는 현재 로컬 기본값을 사용합니다. 비밀 키는 시작의 필수 조건이 아닙니다.
- CORS는 로컬 프론트 출처 `http://localhost:5500`, `http://127.0.0.1:5500`를 기본 허용합니다.
- 허용 방식은 GET·POST·PUT·DELETE·OPTIONS, 허용 요청 헤더는 Content-Type입니다. 쿠키·인증 정보 전달은 현재 사용하지 않습니다.
- CORS는 앱 바깥에 적용해 정상·검증 실패·서버 오류 응답 모두에 필요한 헤더를 붙입니다. 브라우저의 preflight 응답은 CORS 미들웨어의 프로토콜 응답으로 처리합니다.
- CORS는 인증이나 접근 권한 검사를 대신하지 않습니다.

설정의 상세한 준비 방법은 [2단계 안내](SETUP.md)를 참고합니다.

## 7. 검증 결과와 재실행

3단계 86개, 4단계 103개, 5단계 128개에 이어 현재 6단계까지 총 **156개 테스트**를 통과했습니다. 대화 조건 병합·메시지 보존·목록 필드 분리·동시 저장·한도·실패 시 무변경을 포함합니다. 실제 클라우드 검증과는 구분합니다.

현재 설치된 Starlette는 기존 `httpx` 기반 TestClient 사용에 전환 예정 경고 1개를 표시합니다. 테스트는 통과했으며, 이 경고 때문에 API가 실패하지는 않습니다. 테스트 도구 전환은 이후 호환성을 검토할 때 반영합니다.

```powershell
New-Item -ItemType Directory -Path .tmp -Force | Out-Null
.\.venv\Scripts\python.exe -m pytest --basetemp=.tmp/pytest-step3
```

임시 경로는 `M1-2` 내부에서 사용합니다. 위 테스트 자체는 오프라인 검사입니다. 현재 전체 206개가 통과했습니다. 별도로 실제 Firestore CRUD·요약·GPT 상담 5개 시나리오·대화 재조회를 확인했습니다.

설계와 구현 기준을 참고한 문서: [FastAPI의 역할별 파일 구성](https://fastapi.tiangolo.com/tutorial/bigger-applications/), [오류 처리](https://fastapi.tiangolo.com/tutorial/handling-errors/), [CORS](https://fastapi.tiangolo.com/tutorial/cors/), [Pydantic 검증](https://docs.pydantic.dev/latest/concepts/validators/).
