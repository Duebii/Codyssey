# 김실장 · 8단계 웹 화면

2026-10-22, 바닐라 HTML/CSS/JavaScript 화면을 실제 FastAPI·Firestore·GPT에 연결했습니다. 프레임워크나 프론트엔드 패키지 설치는 필요하지 않습니다. 이 문서의 시험 수치는 8단계 검증 시점의 기록입니다. 2026-10-27 완료한 실제 배포 주소와 후속 검증은 [README](../README.md), [배포 안내](DEPLOYMENT.md)를 참고합니다.

2026-10-27에는 사용자가 선택한 차분하고 세련된 분위기로 화면을 다듬었습니다. 잉크 블루·한글 서체·흰 작업 면·작은 화면의 메뉴 배치와 메모 펼치기를 개선했습니다. 데이터와 API는 그대로이며 요청 처리 테스트 14개가 다시 통과했습니다. 자세한 기준은 [UI_DESIGN.md](UI_DESIGN.md)에 있습니다.

## 로컬에서 열기

`M1-2` 폴더에서 터미널 두 개를 사용합니다. 이미 같은 서버가 실행 중이면 중복 실행하지 않습니다.

백엔드:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

프론트엔드:

```powershell
.\.venv\Scripts\python.exe -m http.server 5500 --bind 127.0.0.1 --directory frontend
```

[김실장 웹 화면](http://127.0.0.1:5500), [Swagger](http://127.0.0.1:8000/docs)를 엽니다. `index.html`을 파일로 직접 열면 모듈과 API 연결이 제한될 수 있으므로 위 주소를 사용합니다. 정적 서버는 `frontend/`만 공개합니다.

## 연결과 역할

- `frontend/index.html`: 의미 있는 HTML, 라벨, 네 화면과 입력 폼.
- `frontend/styles.css`: 공통 색·간격, 모바일·태블릿·데스크톱 배치, 포커스·모션 감소.
- `frontend/app.js`: 화면 상태, API 연결, 안전한 텍스트 렌더링, 폼과 대화 흐름.
- `frontend/lib.js`: 공개 API 클라이언트, 단위·날짜 표시, 조건 변경분과 입력 변환.
- `frontend/config.js`: 공개 `API_BASE_URL` 한 개. API 키·Firebase 키는 넣지 않습니다.

모든 기록과 답변은 시연용 가상 데이터라는 점을 표시합니다. 상담의 질문·답변은 성공한 응답 뒤 Firestore의 `conversations`에 자동 저장됩니다. ‘작업 기록’의 완료한 작업 데이터와는 별개입니다.

2026-10-28부터 질문·상담 종류·현재 상황·열어 둔 상담 ID·읽던 위치를 브라우저에 임시 보관합니다. 탭의 `sessionStorage`를 우선 사용하고 `localStorage`에 마지막 작업실을 백업합니다. 새로고침은 같은 탭의 내용을, 새 탭이나 다시 접속할 때는 마지막 브라우저 백업을 복원합니다. 이미 열린 다른 탭의 입력을 실시간으로 덮어쓰지 않습니다. API 주소별로 보관을 분리하며 서버 키와 대화 메시지 전체는 브라우저에 저장하지 않습니다. 브라우저 데이터를 지우거나 다른 브라우저·주소를 사용하면 초안은 이어지지 않습니다. 저장소가 차단되거나 가득 차면 가능한 탭 보관으로 전환하거나 복사 안내를 표시합니다.

새 상담·다른 상담을 열어도 미전송 초안을 남기며, ‘이전 상담’의 ‘작성 중인 질문’에서 다시 엽니다. 완료된 대화는 GET으로 다시 불러옵니다. 응답 대기 중 페이지가 다시 열리면 유료 요청을 재전송하지 않고 저장 확인을 안내합니다. 기존 상담에 같은 질문의 새 메시지가 저장된 것이 확인되면 해당 미전송 표시를 정리합니다. 조회에 실패하면 초안을 유지하며, 기존 상담을 불러오기 전에는 새 상담으로 잘못 보내지 못하게 합니다. 기록 입력 폼의 내용은 저장 요청이 실패하면 유지합니다. 기록 폼의 새로고침 복원은 이번 변경 범위에 포함되지 않습니다.

첫 질문 전에는 기존 안내·참고 기록 화면을 사용합니다. 질문을 보내면 넓은 채팅 화면과 아래 입력칸으로 전환합니다. 참고 기록은 버튼으로 펼치고, 긴 새 답변은 시작 부분부터 읽습니다. ‘새 상담’을 누르면 첫 화면으로 돌아옵니다.

불러온 120분 조건을 그대로 매번 전송하면 ‘60분으로 줄었어요’라는 후속 질문과 충돌할 수 있습니다. 그래서 화면에서 실제로 바꾼 필드만 `context`에 보내고, 바꾸지 않은 필드는 생략합니다. 비운 값은 `null`, 비운 할 일은 `[]`로 보내 명시적으로 해제합니다. 응답을 받으면 서버가 확정한 최신 조건을 폼에 반영합니다. 저장 충돌 후 최신 대화를 불러와도 작성 중인 질문·바꾼 조건·상담 종류를 보존하며, 바꾸지 않은 조건만 최신 서버 값으로 갱신합니다.

실행 계획은 해당 메시지 당시의 작업명으로 렌더링합니다. 작업 단계 합계와 여유 시간을 함께 보여주고, 미룬 작업·가정·점검·대안을 구분합니다. 과거 답변의 근거 버전은 새 요약 버전으로 바꾸지 않습니다.

## 로딩과 실패 처리

전송 중에는 새 상담·상담 종류·대화 불러오기·질문 입력을 잠시 막습니다. 12초가 지나면 기다리는 이유를 안내합니다. GPT 요청은 최대 160초 기다리며 자동 재전송하지 않습니다. 답변 완료는 별도의 짧은 `role=status`·`aria-live=polite` 알림으로도 전달합니다. 연결·시간 초과·저장 여부가 불확실하면 ‘이전 상담’을 먼저 확인하도록 안내합니다.

기록 추가·수정이 성공하고 요약 갱신만 실패하면 ‘기록은 저장됐어요’와 서버 경고를 함께 표시합니다. 목록·요약의 조회 실패는 해당 영역에서 재시도할 수 있습니다. 삭제 시에는 기록 한 건과 상담 전체의 범위, 되돌릴 수 없음을 확인합니다.

메모·질문·AI 출력은 `textContent`로 표시합니다. 외부 텍스트를 HTML로 실행하지 않습니다. 빈 데이터는 첫 입력으로 안내하고, 모르는 통계는 `—`로 표시합니다. 미기록 날짜는 휴식·0분으로 해석하지 않습니다.

## 공개 주소를 환경변수로 반영하기

브라우저의 정적 JavaScript는 서버 환경변수를 직접 읽을 수 없습니다. 빌드 도구가 공개 주소 한 개를 `dist/config.js`에 기록하도록 준비했습니다.

```powershell
$env:API_BASE_URL = "http://127.0.0.1:8000"
.\.venv\Scripts\python.exe scripts/build_frontend.py
```

결과는 `dist/`의 공개 파일 6개입니다. `.env`나 서비스 계정 파일을 복사하지 않습니다. 외부 주소에는 HTTPS를 요구하며 인증 정보·쿼리·프래그먼트를 거절합니다. 로컬 개발용 HTTP 주소만 예외입니다. Vercel은 `--production` 빌드로 실제 HTTPS API 주소를 요구합니다. 실제 배포 설정과 CORS는 [10단계 결과](DEPLOYMENT.md)에 기록했습니다.

## 확인한 결과와 범위

- 실제 웹 입력으로 가상 작업 1건을 추가(12분)하고 수정(15분)했습니다. 목록과 요약이 151건·6,539분으로 바뀌었습니다. 메모의 `<b>`도 문자 그대로 표시됐습니다.
- 기록·상담 삭제 확인창의 대상과 범위, 취소·Escape를 확인했습니다. 화면에서 영구 삭제를 실행하지는 않았습니다. DELETE API는 기존 서버 테스트, 프론트 요청·204 응답 처리는 Node 테스트로 확인했습니다.
- 이름·날짜·신규 ID가 일치하는 시험 기록만 별도 도구로 정리했습니다. 원본 150건 전체의 내용 해시가 같고 총 6,524분임을 확인했습니다. CRUD가 발생했으므로 현재 요약 버전은 159입니다.
- 웹에서 GPT 상담 1건을 실제 요청했습니다. 기간·150건·6,524분을 반영한 응답과 자동 저장을 확인했고, 새로고침 후 같은 대화를 불러왔습니다. 현재 상담은 6개·메시지 16개입니다.
- 기존 실행 전략 상담을 불러오면 60분·목표·할 일 2개가 복원되고, 55분 작업+5분 여유 및 미룬 작업이 표시됩니다.
- 별도 로컬 시험 서버에서는 빈 기록·빈 요약·빈 상담, 503 상담 오류 뒤 질문·시간·할 일 보존, 선행 관계 순환 거절을 확인했습니다. 이 시험은 Firestore·GPT를 호출하지 않았습니다.
- 390×844, 768×1024, 1440×900에서 네 화면의 가로 넘침이 없었고, 실제 사용자 창 483×704도 확인했습니다. 키보드 본문 건너뛰기·전송·삭제 취소, 화면별 제목 포커스와 입력 라벨을 확인했습니다.
- Python 215개, Node 14개 테스트 통과. 기존 Starlette TestClient 전환 예정 경고 1개가 있으며 실행 결과에는 영향이 없었습니다.

테스트 실행:

```powershell
.\.venv\Scripts\python.exe -m pytest
node --test tests/frontend.test.mjs
```
